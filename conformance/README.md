# Conformance vectors

Golden vectors produced by the reference Python SDK. A port (Node, later Go and Java) passes
when it reproduces every `expected` value byte for byte from the matching `input`.

## Format

Each file in `vectors/` is a JSON object:

```
{ "description": str, "source": "<python function(s)>", "cases": [ { "name": str, "input": {...}, "expected": {...} } ] }
```

Exceptions: `field-rules-vectors.json` is a verbatim copy of the SDK's own
`tests/vectors/field-rules-vectors.json` (its own `vectors` array and comparison rules, see its `_comment`).
The four files that end in `-vectors.json` and start with `masking` or `fail-closed` are verbatim copies too, of the
SDK's `tests/vectors/` files of the same names. Their cases are `{ "name", "op", "input", "expected" }`: `op` names one
of a small set of operations that each runner implements, and the file's `description` defines every operation it uses
and lists the SDK tests that are not vectorised. A long run of one character is written
`{"$repeat": "a", "times": 65537}`, and a string made of such parts `{"$concat": [...]}`; the runner expands them.

| File | What it pins down |
| --- | --- |
| `blake2b.json` | BLAKE2b hex, digest sizes 8 and 16, unkeyed and keyed |
| `fingerprint.json` | key paths, query names, content-type normalisation, hash input `raw`, request and response fingerprints, value pairs |
| `templating.json` | curated template ordering and matching, heuristic `{id}` fallback |
| `classify.json` | observed type labels and per-body value types |
| `placeholders.json` | format-preserving placeholders (salt handling, hint guards) |
| `mask-all.json` | fail-closed masking of headers, bodies and queries |
| `field-rules-vectors.json` | the SDK's field-rule vectors (copied) |
| `masking-vectors.json` | field rules, project mask rules, header allowlist and image bodies, one case per SDK test (copied) |
| `masking-pipeline-vectors.json` | whole-pipeline masking for known and unknown fingerprints (copied) |
| `masking-values-vectors.json` | format-preserving placeholders, value types, and placeholders through field rules (copied) |
| `fail-closed-vectors.json` | unusable rules, non-JSON bodies, failed syncs, malformed scopes, the regex scan cap (copied) |
| `../regex-corpus.json` | regex masks the API accepts on save, with Python's `re.sub` result per input (copied from the API repo; not a generated vector) |
| `field-rules-extra.json` | status-scoped rules, type hints, scalar-exact keep, regex backstop, project defaults |
| `payload.json` | full `PrivacyPipeline.process` payloads across rules-cache states |
| `refusals.json` | ingest refusal warnings (level and formatted message) |
| `pyfloat.json` | Python `json.dumps`, `str` and `repr` of numbers |
| `pyqs.json` | `parse_qs(keep_blank_values=True)` and `urlencode(doseq=True)` |

### Conventions

- Typed scalars: where int versus float versus string matters (`placeholders.json`, `pyfloat.json`) values are
  `{"type": "str"|"int"|"float"|"bool"|"none", "value"|"text": ...}`. `text` is the Python `repr` for floats
  and decimal digits for ints (ints may exceed 2^63; use BigInt or equivalent).
- JSON bodies in inputs are source text. Parsing must follow Python `json.loads`: ints are arbitrary precision,
  `1` is an int while `1.0` and `1e2` are floats, duplicate keys keep the first position with the last value,
  and `NaN`, `Infinity`, `-Infinity` are accepted.
- Masked output bodies are Python `json.dumps` text: separators `", "` and `": "`, non-ASCII escaped as `\uXXXX`
  (`ensure_ascii=True`), floats printed with Python `repr`, `NaN` as `NaN`. Form and query output is
  `urlencode(doseq=True)` text. Compare these strings exactly.
- Dict-valued expectations are written with sorted keys; ordered data that matters (key paths, parse_qs pairs)
  is stored as lists.
- Placeholder salt: the `STUBSMITH_MASK_SALT` string; empty or null means no key; the key is its UTF-8 bytes
  truncated to 64 bytes.

## Regenerate

```
PYTHONPATH=<path to a Python SDK checkout> python3 tools/gen-vectors.py
```

The generator is deterministic (fixed inputs and salts, sorted keys); two runs produce identical files.
`conformance/VECTORS_VERSION` records the Python SDK version the vectors were generated from and the SHA-256 of
each vector file. It carries no commit id. `test/conformance-version.test.ts`
recomputes the digests, so a vector edited by hand fails the suite.

Expected values are generated by calling the SDK. Never edit them by hand. If a vector looks wrong, fix the SDK
or the generator input and regenerate.
